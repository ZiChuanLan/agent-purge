# agent-purge v0.2.18

### 🌟 核心更新亮点 (Highlights)

#### 1. 🔓 修复多会话启动被 journal 挡住（issue #8）
- **现象**：`omp` / `pi` 在 slash 已常驻时，每次启动都会对同一个扩展文件做一次交换；第二个终端直接报「文件存在未结束的交换」。
- **根因**：常驻的 `~/.omp/agent/extensions/agent-purge.ts` 与启动侧 `extensionSource()` 生成的内容**逐字节相同**，但 `swapFile` 不比较内容，先独占 journal，于是空转的交换也把文件锁到会话结束。
- **修复**：交换前置内容比对 —— 磁盘已是目标内容时直接返回 no-op undo，不建 journal、不加锁。

#### 2. ♻️ 死持有者的 journal 现在会被回收
- 撞到 `EEXIST` 时读取 journal：持有者进程已退出则 `restore` 后重试一次；恢复失败（文件被外部改过）保守报错，不覆盖用户数据。
- 真冲突的错误信息带上持有者 PID，排障不用再翻临时目录。

#### 3. ✅ 安全不变量未变
- 内容真的不同时仍然互斥；`recover()` 仍只回收已死的 v2 持有者；用户外部编辑仍阻止 undo；旧格式 journal 仍只报告不自动覆盖。
