# agent-purge v0.2.16

### 🌟 核心更新亮点 (Highlights)

#### 1. 🧭 「装在哪都认」：桌面端安装位置定位重写
- **四层定位链**：开始菜单/桌面快捷方式 → 各盘常见根（`X:\<名>`、`Program Files`、`Programs`、`Apps`）→ 注册表卸载项 → 盘内浅扫（深度 3、跳过系统目录、每盘 600ms 预算）。
- **换盘不再误报**：WorkBuddy、ZCode、DSH、Antigravity 装在 `F:\`、`D:\` 或任意目录都能识别，不再依赖写死的 `D:/`、`C:/Program Files/`。
- **零额外依赖**：`.lnk` 用纯 JS 解析（不调 PowerShell COM），注册表只在兜底时做定向查询，结果全程缓存。

#### 2. 🪪 不再要求「必须先写过配置文件」
- 配置目录存在即视为安装过；新装的 Claude、Grok、Codex 在还没生成 `settings.json` / `config.toml` 时不再显示「未安装」。
- OpenCode 的判据从单文件 `opencode.json` 放宽到 `opencode.jsonc` / `config.json` / `auth.json` / `plugins` / `node_modules`。
- 所有 CLI 增加 `%APPDATA%\npm`、`~/.bun/bin`、`~/.local/bin`、`scoop\shims` 兜底——GUI 启动继承不到完整 `PATH` 时也能找到命令入口。

#### 3. 📝 修正 WorkBuddy 的「项目规则文件」说明
- 原本文案称「WorkBuddy 没有项目级规则文件可写」并不准确：它会按 `CODEBUDDY.md` → `.codebuddy/CODEBUDDY.md` → `AGENTS.md` 取第一个存在的文件，塞进首轮 `<project_context>`（8000 字符上限）。
- 界面现在如实标注：该通道只是「用户上下文」，压不住系统身份，身份仍走 `settings.json` 的 `customPrompt`。

#### 4. 🧹 其他
- 技术详情新增「安装目录」一行，并标注来源（快捷方式 / 盘符扫描 / 盘内浅扫 / 注册表）。
- 修复 `web/server.mjs` 中重复的 `kilo` 键（会让静态检查报错）。
- `scripts/verify-zcode-real.mjs` 不再写死 `D:/zcode`。

### 📦 安装与升级 (Installation & Upgrade)

#### npm 全局安装 / 升级：
```bash
npm install -g agent-purge@latest
agent-purge web
```

#### 便携版 EXE / 安装器：
可在本 Release 附件中下载最新发布的 `agent-purge.exe`（单文件独立版）或 `agent-purge-0.2.16-setup.exe`。
