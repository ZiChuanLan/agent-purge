# agent-purge v0.2.22

### 🌟 核心更新亮点 (Highlights)

#### 1. 🌍 新增 WorkBuddy AI 国际版支持（5.9.4 实测通过）
- **新增宿主**：`workbuddy-ai`（国际版 WorkBuddy AI，workbuddy.ai），与国内版 `workbuddy` 独立并列，可单独安装/卸载，也可同时装。
- **实测证据**（本机 CDP 直连 renderer，真发消息）：写入人设后提问「你叫什么名字」，回答就是人设里的名字；卸载后配置文件与 `IDENTITY.md`/`SOUL.md`/`USER.md` 字节还原。
- **身份通道**：`personalization.customPrompt`（进 `identity_context` 的 `<user_custom_instructions>`），配合 `~/.workbuddy-ai/user-*/{IDENTITY,SOUL,USER}.md` 同步。

#### 2. 🔧 修复写错文件：`app-config.json` 才是主路径
- **现象**：只写 `~/.workbuddy-ai/settings.json` 时，WorkBuddy 设置面板仍显示旧值，新任务也不按新人设作答。
- **根因**：WorkBuddy 的 `PersonalizationCollector` 先读 `AppConfigService.get("personalization")`，只有拿不到才 `readLegacySettings()` 回落 `settings.json`。而 AppConfigService 的主存是 `<home>/app/app-config.json`。国内 5.9.3 与国际 5.9.4 行为一致（两者都写时以 `app-config.json` 为准）。
- **修复**：`app-config.json` 存在就写它，不存在（更老的版本）才写 `settings.json`；安装/卸载都会把另一份里 agent-purge 自己写过的 marker 块清掉，别人的文本原样保留。写入位置不再随「用户点没点过设置面板」漂移。

#### 3. 🈶 修复中文安装目录定位失败
- **现象**：WorkBuddy 装在 `D:\WorkBuddy国际版\WorkBuddyAI` 时，agent-purge 认不出（`findTemplatesDir` 返回 null、`detect` 报未安装）。
- **根因**：`.lnk` 的 `LocalBasePath` 是系统 ANSI 码页（中文机 936/GBK），`lib/locate.mjs` 却按 `latin1` 解码，得到 `D:\WorkBuddy¹ú¼Ê°æ\...`，这个路径根本不存在。
- **修复**：按注册表 `ACP` 选码页解码（gbk / big5 / shift_jis / euc-kr / windows-1252），取不到或非法字节退回 latin1。修好后 `locate` 直接命中 `D:\WorkBuddy国际版\WorkBuddyAI\WorkBuddyAI.exe`。

#### 4. 🧩 国际版识别与能力表
- `detect` 新增 `workbuddy-ai` 规格（`WorkBuddyAI.exe`、`~/.workbuddy-ai` 配置根、`WORKBUDDY_AI_CONFIG_DIR` / `WORKBUDDY_AI_TEMPLATES_DIR` 环境变量）。
- Web 控制台图标、sys 层映射、`caps` 桌面优先与项目级规则说明补齐。

---

### ⬆️ 升级注意

- 国内版与国际版的写入位置都改成了 `app/app-config.json`（若该文件存在）。之前写进 `settings.json` 的块会在下次 `install` 时自动撤走。
- 名字/人设设定仍是 WorkBuddy 自己的云端个人配置，agent-purge 不写入、也不清除。

### 📦 安装与升级 (Installation & Upgrade)

```bash
npm install -g agent-purge@latest
agent-purge install workbuddy-ai   # 或 workbuddy / 两者都装
```

便携版与安装器见本 Release 附件（`agent-purge.exe` / `agent-purge-0.2.22-setup.exe`）。
