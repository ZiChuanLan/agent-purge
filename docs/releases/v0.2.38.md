# agent-purge v0.2.38

### 🔍 WorkBuddy：找到真正的系统提示词入口（桌面端真替换）

- 之前只写 `personalization.customPrompt`，它进的是 user 消息里的
  `identity_context` / `user_custom_instructions`，不是 system 层。这次在 5.11.3 上把入口
  定位出来了：桌面端真正渲染进 system 的是插件缓存
  - `~/.workbuddy/plugins/cache/workbuddy-builtin/welcomemode-{code,work,design,claw}/<ver>/prompt.tpl`
  - `~/.workbuddy/plugins/cache/workbuddy-builtin/interactionmode-{ask,craft,expert,plan,quick}/<ver>/fragments/*.md`
  - `~/.workbuddy/plugins/cache/workbuddy-builtin/prompt-common/<ver>/fragments/*.md`

  安装目录 `resources/templates/` 下那 12 个 `workbuddy-*.tpl`（31K 主提示词）桌面端根本不读，
  只有 `user-context-identity.tpl` 还在用，而它也只落在 user 消息的
  `<system-reminder data-role="user-context">` 里。
- 判定方法：给每个候选文件注入唯一标识，真实桌面会话里看模型是否原样复述。
  命中 `welcomemode-work`、`interactionmode-craft`、`prompt-common` 三个；
  `resources/templates` 的 12 个模板全部没有出现。请求体在客户端加密（TLS 明文层是 base64
  密文，解码后不是 JSON），所以证据取自模型输出侧而不是抓包。

### 🧩 双通道改造

- `welcomemode-*/prompt.tpl`：`replace` / `strict` 整份替换（这才是真替换），`append` 保留原文。
- `interactionmode-*/fragments/*.md`：一律追加，不抹掉工具与工作流说明——那些片段里没有安全条款，
  删了只会把工具用法弄坏。
- 版本目录按 semver 取当前版本，跳过带 `.orphaned_at` 的旧副本；升级后缓存目录会换，需要重装。
- `persist` 侧 `workbuddy` / `workbuddy-ai` 都改成双通道：系统提示词写插件缓存，身份上下文仍写
  `personalization.customPrompt`（国际版以 `app-config.json` 为主）；`probe` 两者取或，卸载按
  stash 原字节还原。
- 国际版 `~/.workbuddy-ai` 结构一致（没有 `welcomemode-claw`，`prompt-common` 多一个
  `wecom-cli-routing.md`），文件层 install/uninstall 已跑通，但本机没有国际版程序，未做真机会话验证。

### 🧹 护栏清理的边界写清楚

- 装上 `strict` 后，`welcomemode/prompt.tpl` 里的护栏关键词从 143 处降到 4 处，`interactionmode`
  片段那 36 处命中全是工具规则（别提工具名、别猜参数、别自己算时间戳），与安全无关。
- 实测对照同一模型：未装时说教一段，装后只答「不会。」；让模型自陈依据，它回答「提示词里没有
  针对破解或侵权的条款」。
- 也就是说：能清的是宿主写在提示词里的说教、免责与替代方案；清不掉的是模型自身对齐的价值观。
  这条边界写进兼容性文档，避免把「净化」理解成「模型没有底线」。
