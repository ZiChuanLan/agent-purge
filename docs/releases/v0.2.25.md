# agent-purge v0.2.25

### ✨ 新支持 (New Support)

#### 1. 🚀 Antigravity（Google 桌面 App + CLI `agy`）接管支持
- **背景**：此前 Antigravity 在矩阵里是 `binary-patch / inject: false`，`agent-purge antigravity` 只打印一句「改不了」。逆向确认后结论变了：**配置层有可写入口，不需要动二进制**。
- **注入落点**：`~/.gemini/config/AGENTS.md`。桌面 App 与 CLI `agy` 共读同一个 `~/.gemini/config/`；该文件没有 frontmatter 就是 `always_on` 全局规则，宿主自己把它拼进 `systemInstruction` 的 `<user_rules>` 段，并在前面写明 `These rules take precedence over any other instructions`。
- **实测证据**（本机 CLI `agy` 1.5.3 / 桌面语言服务 1.23.x，隔离 HOME + loopback 抓包）：
  - `off / strict / replace / append` 四模式均捕获主请求，进程退出码 0；
  - marker 全部落在 **system 层**（`systemInstruction`），`user` 层 0 次；
  - system 字符数 15,378（off）→ 15,895 / 15,844 / 15,843（strict / replace / append）；
  - `<user_rules>` 位于 `</identity>` **之后**，即规则段排在宿主身份句后面。
- **真模型验证**：CLI 登录后，在**同一落点**（`~/.gemini/config/AGENTS.md`，手写同语义内容）连真实模型问三句（直问身份 / 追问底层模型 / 越狱式要求说出真名），三次都回答新人设、不再自称 Antigravity。agent-purge 自己写入的托管块则由上面的抓包链路验证落在 `systemInstruction` —— 两者是同一条通道；「agent-purge 写入 + 真模型」的单一跑批因本机代理中断未做（NOT RUN）。
- **残留（不隐瞒）**：`<identity>` 里那句 `You are Antigravity, ...` 仍在提示词中，靠规则段的优先级声明压住，**不是删除**。想真正删掉身份段只有两条路：等长替换 `resources/bin/language_server.exe`（会让签名失效、更新被覆盖），或手动在 GUI 里选自定义 agent（`~/.gemini/config/agents/<name>.md` 能整段替换 `<identity>`，但 `settings.json` 里没有默认 agent 键，34 个键全试过，做不到自动生效）。
- **通道能力**：只有 `install`（常驻配置）可用；`shim` 不可用（CLI 命令名是 `agy` 而非 `antigravity`，裸命令接管的落点名对不上），`slash` 不可用（无 `/purge` 等价入口）。
- **CLI 探测**：`agy` 装在 `%LOCALAPPDATA%\agy\bin\agy.exe`，GUI 进程继承的 PATH 常常没有这一项，所以 detect 增加了固定落点回退，并额外把 `~/.gemini/config` 当作「跑过这个 App」的判据。

#### 2. 🔍 抓包链路支持 Gemini 原生协议
- `bench/capture-provider.mjs` 之前只认 `system` / `instructions` / `messages` / `input` 四种字段，Gemini 的 `systemInstruction.parts` + `contents[]` 完全抓不到（会被判成「没有 system 层」）。
- 现在补上 Gemini 原生协议：请求识别（`/v1beta/models/<model>:streamGenerateContent`）、system 段提取（`systemInstruction.parts`）、SSE 响应（`candidates[].content.parts`）。`agent-purge verify antigravity` 可直接复用这条链路。

### 🔧 修复 (Fixes)

- **`shim` 能力判定会把「名字对不上」翻成可用**：`antigravity` 的 CLI 叫 `agy`，`resolveReal("antigravity")` 永远为 `null`，但旧逻辑 `!shimWhy || (desktop && hasCli)` 在有 bin 时会把这条通道标成可用，导致 UI 上出现一个点了没用的开关。现在对「CLI 名字与 harness 名不一致」的家加了显式黑名单，先给出真实原因而不是撒谎。

- **临时启动会撤掉常驻块**：最初把「单次启动」实现成 install → uninstall，实测发现用户若先 `arm --install` 常驻过，`agent-purge antigravity` 跑完会把常驻块一起删掉（`stash.before` 为 null → 卸载走删文件分支）。改为按**原字节回滚**（`temporaryAntigravity`），常驻块、用户自己的规则都原样留下，并补了三条回归测试（常驻在场 / 干净机器 / 用户自带规则）。

### 📦 安装与升级 (Installation & Upgrade)

```bash
npm install -g agent-purge@latest
agent-purge arm antigravity --install
```

> 需要先装好 Antigravity（桌面 App 或 `agy` CLI）。`agent-purge antigravity` 也可直接带人设启动 CLI，退出时按原字节还原。

便携版与安装器见本 Release 附件（`agent-purge.exe` / `agent-purge-0.2.25-setup.exe`）。
