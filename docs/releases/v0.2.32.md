### 🎯 新增 `replaceScope`：把「替换」拆成四种

以前「替换」一词把三种完全不同的效果混成一种。现在每家都标清楚：

| 范围 | 含义 |
|---|---|
| `entire-system` | 整份换掉，只剩人设 |
| `identity-only` | 只换身份段，工具说明与运行规则仍在 |
| `append` | 没有整段入口，人设只是追加，原生身份仍在 |
| `client-field` | 宿主 system 在服务端拼装，客户端只有一个字段可换（Auggie） |

`test/mode-support.test.mjs` 强制 append 型不许标成别的。

### 🛡 内置护栏实测

17 家里只有 4 家的 system 提示词真带「拒答 / 防破甲 / 防注入」条款。CodeBuddy、Claude、Qoder、DSH 在 replace 后仍有残留（Qoder 剩 1 条写死在 CLI 常量里的 133 字前缀，Claude 剩 1 条在 user 角色的 system-reminder 里，DSH 剩 2 条 web_search / web_fetch 的防注入句）。UI 里「未测」显式标黄，绝不与「已清干净」长得一样。

### 🚪 移除 Gemini CLI

Gemini CLI 已不再受支持（移除前最后一次实测是 30,425 → 116，护栏 1 → 0），从宿主列表里彻底移除：`matrix.json`、`backends`、检测、路径映射、规则文件、抓包适配、图标、三语文档全部清掉，宿主数 24。

保留的是 **Gemini 协议**：Antigravity 仍走 `systemInstruction`，magpie 的 `geminiSystem` 改写函数与假 provider 的 Gemini 分支因此留着。

### 🕓 kiro / goose 标为「未来支持」

这两家还没确定能不能接管（kiro 不登录抓不到请求；goose 只能追加、顶不掉原生身份），UI 里灰掉标「未来支持」，不再画成「可接管」。

### 🔌 点名启动通道补进能力表

`lib/caps.mjs` 新增 `launch` 通道，判据直接取 `backends` 的实际实现。以前 `launch-arg` 型宿主四条通道全不命中，UI 落到「仅支持项目级规则文件」的兜底文案——把明明在注入的工具说成注入不进去。现在卡片显示「缺命令行 / 点名启动」，抽屉给出可复制的 `agent-purge <宿主>` 命令。
