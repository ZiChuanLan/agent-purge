# agent-purge v0.2.27

### ✨ 改进 (Improvements)

#### 1. ⬆️ 源码检出也能一键更新：在本目录 `git pull`，不再下载发布产物

以前只有两种形态被识别：独立 EXE 走热替换，其余一律当成 npm 全局安装。于是 `git clone` 后直接 `node bin/agent-purge.mjs web` 的人点「一键升级」，实际执行的是 `npm install -g agent-purge@latest` —— 装的是另一份全局副本，**正在跑的这个仓库一点没动**。

现在多出第三种形态 `git`：

| 安装形态 | 判定 | 一键更新做什么 |
|---|---|---|
| `exe` | 编译产物 + Windows + 非共享 node/bun | 下载 Release 的 `agent-purge.exe`，校验长度与 sha256 后就地热替换 |
| `git`（新增） | 安装目录里有 `.git` 且不是编译态 | 在安装目录执行 `git pull --ff-only` |
| `npm` | 其余 | `npm install -g agent-purge@latest` |

三条约束，都是为了别把工作区弄坏：

- **`--ff-only`**：从面板点出来的更新不该悄悄造一个合并提交。本地有未推送提交时会直接失败，由人决定怎么办。
- **工作区不干净就拒绝**：有未提交改动时不动任何文件，报「工作区有 N 处未提交改动」。
- **游离 HEAD / 分支没有上游都拒绝**：不猜 `origin/main`。

「有没有更新」也分两种：

- 版本号变了（有新 Release）→ 角标显示 `v0.2.26 (发现 v0.2.27)`
- **上游只是多了提交、版本号没动** → 角标显示 `v0.2.26 (上游 N 个新提交)`，弹窗里「最新」显示成「N 个新提交」。这一项只有手动刷新才 `git fetch`，平时开面板不会连 GitHub。

CLI 同步：`agent-purge update` 会先打印安装形态；源码检出加 `--download` 才真的执行 `git pull`，否则只给出命令。

#### 2. 🐛 拉取失败不再伪装成「已是最新」

实测时网络断掉，`git pull` 非零退出，但 stderr 被当成 `output` 返回，面板显示成「当前分支 main 已是最新」。现在非零退出直接抛错，界面显示真实原因。

---

### 📦 安装与升级 (Installation & Upgrade)

```bash
npm install -g agent-purge@latest           # npm 安装
git pull --ff-only                          # 源码检出，在安装目录执行
```

便携版与安装器见本 Release 附件（`agent-purge.exe` / `agent-purge-0.2.27-setup.exe`）。
